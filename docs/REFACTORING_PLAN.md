# リファクタリング設計案

基準: develop の 48bbe8d。段階1「診断専用コードの撤去」は実機確認済み。段階2は実装・ビルド・27項目のチェック済み。ユーザーによる実機動作確認と差分レビューも完了。段階3は①の例外保護を実装、実機確認待ち。

段階1ではLayoutDiagnostics、診断用Harmonyパッチ7個、追跡用ログ、未使用のPresetSummaryとそのテスト1項目を撤去した。終了理由引数はログだけで使っていたためEnd()へ変更。代替処理は追加せず、既存の警告・エラーログを維持する。削除コードはGitの基準コミットから復元可能。

段階1の確認対象は全カテゴリのモデル更新、通常編集の確定・取消、現行のオブジェ一覧。段階1では毎フレーム処理・キャッシュ・例外処理・保存形式を変更していない。

## 維持する境界と仕様

- Modが書く永続データは専用プリセットJSONのみ。保存形式はschema 2、schema 1の読込互換も維持する。
- プリセット読込は公式APIで未確定の編集配置へ反映する。ゲームの確定・取消を置き換えず、セーブAPIや実効果データへ直接書き込まない。
- 保存・読込・削除、6スロット、名前入力、空き読込スロットの操作、戻る経路、A/Bガイド、プレビューを維持する。
- Transmog公開APIによる抑止、単独動作、旧版のタイトル判定を維持する。
- 壊れたプリセットJSONは既存ファイルを上書きせず保存を停止し、公式の編集は使える状態を維持する。破損時にMod入口そのものを消す変更は今回の仕様維持とは分ける。
- 警告・エラーログは残す。削除対象は診断トレースと開発中の正常系ログ。

## 3. 設計判断が必要な改善

承認済みの方針:

- ① 想定外のUI例外では、その編集セッションのプリセット機能を停止。公式の編集画面を閉じて再表示すると再試行できる。通常の保存失敗や事前検証エラーは従来どおり扱う。
- ② 読込失敗は、適用前失敗・復元確認済み・復元不能に分ける。復元不能時はプリセットを停止し、確定せず公式の取消を行うよう案内する。自動確定・強制取消は行わない。配置と3D表示の更新結果を分けて扱う。
- ③ 翻訳は選択言語JSON→英語JSON→DLL内蔵英語。内蔵英語はen.jsonからビルド時に取り込み、二重管理を避ける。

①の初版は通常UIと破損データの実機確認済み。レビュー指摘の非同期ダイアログ解放を修正し、ビルド・35項目のチェック済み。修正版の実機確認と、ゲームUIでの例外注入検証は未実施。②③と取消・UI依存の改善は未実装。

①の変更記録:

| 置換対象 | 理由・置換先 | 影響と確認箇所 |
| --- | --- | --- |
| Guardの例外→Abort | Abort自身が失敗し得るため、ReportFaultで停止フラグと世代更新を先に行い、独立した後片付けへ | 想定外例外時の停止・再表示による解除 |
| 保護されていないパッチ・完了コールバック | 各入口で例外を受け止める。入力を既に引き受けた場合、同じ入力を公式へ二重に渡さない | ＋、Y、空きスロット、名前入力、完了画面 |
| ClearStateの一括リセット | 管理状態だけをResetMenuStateへ抽出。異常経路ではUnity操作の失敗と独立してリセットする | 古いコールバックの無効化、プレビュー・タイトル・フッター復帰 |
| 起動時のtry範囲 | 初期化も保護。起動失敗時に限り自分のパッチを解除する | 初期化失敗が公式操作へ波及しないこと |

異常時に閉じるダイアログは、公式UIManagerのCurrentUIKeyと現在のページを取得し、Mod専用TextId/infoIdで所有確認する。キーボードは既存のコールバック同一性確認を使う。所有を確認できないUIは閉じない。後片付けに必要な公式APIも失敗する場合、UIの完全復帰までは保証せず、例外を外へ漏らさないことを優先する。

追加自動チェックは後片付け本体の例外・ログ側の例外を注入して検証する。ゲーム内ダイアログの非同期表示・終了中に異常が起きる場合は別途実機検証が必要。通常利用版に例外注入用のキーや設定は追加していない。

### 例外境界とMod停止

実装前はDriver経由はGuardを通るが、一部のHarmonyコールバックは直接Mod処理を呼ぶ。従来のGuardのAbortもタイトル復元などで例外を起こし得た。

採用方針: 入口ごとに例外境界を置き、古いコールバックの世代を無効化し、Mod所有のUIだけを解放する。障害後に新しいプリセット操作を受け付けるか、編集セッション終了まで停止するかは挙動変更に当たるため、実装前に影響を整理する。公式ダイアログを一律に閉じたりHarmony全体を解除したりしない。

### 読込失敗の復元

現在も読込直前のスナップショットを復元する設計。ただしRestoreはSetCustomPartsの例外を記録して続行し、復元結果の一致確認はない。失敗時の「読み込み前へ戻しました」という表示を常に保証できない。

案: 復元結果の照合と、復元できなかった場合の停止・通知を別途設計する。失敗通知を増やすこと、通常編集の継続を制限することは仕様差分になるため、この整理に紛れ込ませない。既存の適用順序や所持数判定は変更しない。

### 名前入力の取消コールバック

SaveNameはnameInputOpenをfalseにしてから失敗時にReturnToSaveSlotsを呼ぶが、後者はfalseだと何もしない。別の取消コールバック経由では実機確認済み。公式の結果通知と取消通知の順序を確認してから扱う。戻り先を変える修正は今回の単純な整理に含めない。

### 翻訳ファイルの破損

JSON読込例外はファイル単位で処理されるが、ディレクトリ列挙失敗やnullの翻訳値は別途考慮が必要。案は起動処理の例外境界と翻訳値検証。現状の「不足キー→英語→キー文字列」と「バニラ表示への退避」は異なる仕様なので、破損時にどの範囲のUIを抑止するかを先に決める。

### 固定配置・文字列・階層への依存

- プレビューは公式のUIBazaarMaxPriceCustomLogPageとUICustomPartsListItemを再利用済み。カテゴリ対応も公式pageToCategoryListを優先している。
- 11行の前提、フォールバック順序、親Transform、左右オフセットは残る。公式の行コレクション・レイアウトコンポーネントで同じ配置を得られるか調べる。見た目が変わるため一括置換しない。
- タイトルは日英の文字列照合に依存する。UIPageHeaderの所有関係や公式TextIdで特定できるか調べる。多言語でのタイトル変更は対応範囲の拡張として扱う。
- ShowPage PrefixとPostShow Postfixは初期表示の取得タイミングに関係する。重複に見えても実機の初回表示を確認するまで片方を削除しない。
- フッターのSetGuide、公式KeyboardManager、公式ダイアログ、未確定配置のSetCustomParts、モデルのRefreshBazaarPartsModelを引き続き利用する。

### ① レビュー指摘への対応: 表示待ち・終了待ちの後片付け

一度だけのCloseOwnedFaultDialogでは、例外発生時にまだ表示されていない画面を取り逃がすため、停止中のTickFaultCleanupへ移した。停止後も編集セッション終了まで所有確認を継続する。通常のプリセット操作・ナビゲーションは再開しない。公式の破棄・退出判定は停止判定より先に行う。

通常のCloseDialogと異常時のCloseDialogはDialogCloseTrackerで終了待ち状態を共有する。例外でナビゲーションの世代が無効になっても、終了通知は待ち状態を解放する。Begin/Endで追跡世代を更新し、前の画面の遅延通知が新しい終了待ちを解除しないようにした。フッターは閉じ終わった後に復元する。

公式APIそのものが例外を返す場合はFaultCleanupFailedを記録し、そのセッションでの後片付けの反復を止める。終了通知が返らない場合にタイムアウトで強制再Closeする処理は設けない（二重終了による公式UIへの影響を避ける）。

追加6項目は実際に使用する追跡クラスの状態遷移を検証する。表示前の待機→遅延表示、二重終了の抑止、終了完了、終了中の障害によるナビゲーション無効化、古い終了通知の無視、新しいセッションの終了を対象とする。Unityの所有判定やアニメーション自体を実行するテストではないため、ゲーム内での例外注入検証とは区別する。
### ① 終了コールバックの準備失敗

TryBeginの後でIL2CPPコールバック作成が失敗すると、公式CloseDialog未呼出しでも終了待ちが残っていた。通常終了・異常時終了の両方をTryPrepareへ置換し、準備失敗時だけ同じ追跡世代の予約を解除して例外を再送出する。公式API呼出し後は、既に終了処理が始まっている可能性があるため予約を解除しない。

追加5項目で準備失敗時の元例外・待ち解除・未送信、再準備、API呼出し段階の失敗後の二重終了抑止、終了通知、重複時に準備処理が実行されないことを確認。ビルドと計40項目が成功。Unity上での例外注入は未実施。通常の画面遷移と異常時の終了経路が変更箇所となる。
最終修正版はユーザーによる正常系の実機確認と差分レビューが完了。40項目の自動チェック成功。ゲーム内の例外注入検証は未実施。公式API自体の失敗や終了通知が返らない場合に完全復帰を保証しない範囲はユーザー了承済み。

## ② 読み込み失敗時の復元照合（実装済み・実機確認待ち）

旧Restoreは各枠への設定を試すだけで結果を確認していなかったため、LayoutTransactionへ適用と復元をまとめ、現在の配置を再取得して照合する方式へ置換した。設定途中で例外が発生しても全枠の復元を試み、最終的に一致した場合だけRestoredと判定する。照合失敗・照合不能はRecoveryUnconfirmedとする。

適用前のSnapshot/Plan失敗は「配置は変更していません」、復元確認済みは既存の復元済み通知を表示。復元を確認できなかった場合はプリセットの入口と＋ガイドを止め、確定せず公式編集を取り消すよう通知する。通知を自動的に閉じるSessionFaultedとは別の停止フラグを使用し、Beginで解除する。自動確定・自動取消・セーブAPIへの書き込みは追加していない。

3Dモデル更新は配置トランザクションの外へ分離。正常適用では変更枠、復元確認後は全元枠のモデルを更新する。更新要求が例外を返す／店舗を取得できない場合は表示更新の失敗として通知し、配置が復元されたと誤報しない。ただし公式API内部の非同期モデル読込完了まで保証する判定ではない。

置換の影響箇所は通常読み込み、読み込み失敗後の一覧への復帰、復元不能通知と公式取消、全カテゴリのモデル更新。保存処理・所持数の事前検証・適用順序は維持した。日英JSONに4種類の通知を追加した。

ゲーム操作を注入できるLayoutTransactionに9項目を追加し、計49項目とビルドが成功。部分適用後の例外、途中の復元失敗でも他枠を復元すること、照合不能、黙って拒否するAPI、書き込み後に例外を返すAPIを検証。これは実際に使用するロジックの自動検証であり、ゲーム内の例外注入と通知レイアウトは未確認。③の内蔵英語などは未実装。
## ③ 翻訳の内蔵英語フォールバック（実装済み・実機確認待ち）

Localization内のファイル読込・キー選択をTranslationCatalogへ置換した。従来は英語JSONも失われるとキー文字列を表示し、null値をそのまま返し、ディレクトリ列挙例外が起動処理へ伝播していたため。選択言語JSON→外部英語JSON→DLL内蔵英語の順で取得し、null・空・空白だけの値は無効として次の候補へ進む。

内蔵英語はen.jsonをEmbeddedResourceとしてビルド時に取り込む。手書きの英語辞書を追加せず、外部翻訳が読めない場合も同じ文言を使えるようにした。未知の開発用キーは従来どおりキー文字列を返す。公式テキスト・言語選択・スロット名の書式・プリセット保存処理・画面遷移は変更しない。

変更の影響箇所はMod文言の取得のみ。通常の日英表示、外部JSONがない場合の英語表示を実機で確認する。破損・欠損・null/空白値・フォルダアクセス失敗・内蔵英語全キーについて実コードを使う12チェックを追加し、計61件成功、Releaseビルドは警告0・エラー0。

②は正常系と不正ItemIdの適用前拒否の実機確認、差分レビューが完了し、801e763でプッシュ済み。途中適用失敗・復元不能の実機故障注入は未実施（自動チェックで検証）。
