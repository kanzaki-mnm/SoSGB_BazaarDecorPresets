# Bazaar Decor Presets 再設計案

2026-09-22。今回の成果物は設計。0.1.0のコード・DLLは変更しない。

## 1. 目的と最優先条件

「料理用」「加工品用」など、バザールの実配置を名前付きで保存し、通常の装飾編集に読み込む。
最優先条件は、Modの故障をMod内に閉じ込め、終了後にDLLとMod専用データを外せばバニラでプレイを続けられること。

ここでいうバニラへの復帰は、Mod独自の型・ID・セーブ形式・効果計算への依存を残さないこと。ユーザーがゲームの通常操作で確定・セーブした合法な配置まで、アンインストール時に以前の配置へ巻き戻す意味ではない。
Modの読込機能は編集配置までを扱い、確定・ゲームセーブは通常操作に委ねる。起動時の自動適用はしない。

ゲーム本体DLL、共有マスタ、アイテム所持数、進行度、ゲームセーブファイルは直接変更しない。
実効果の数値や効果判定にHarmonyパッチを当てない。未知のID・空欄規則・数量規則は推測で通さない。
ネイティブAPIの異常まで絶対に無害とは断言できないため、編集と確定済み状態の分離を実証できない適用経路は配布版で有効にしない。

## 2. 参照したTransmogの現行実装

パスは `../SoSGB_BazaarDecorTransmog/BazaarDecorTransmog/` 基準。

| 参照 | 取り入れる点 | そのまま取り入れない点 |
|---|---|---|
| `PresetUiController.cs` | 標準ダイアログ、名前入力、閉じ終わった後の遷移、コールバックの世代管理、所有UIだけの後片付け | AppearanceSessionへの依存 |
| 同 `OpenNameInput` / `IsOwnNameInput` | `KeyboardManager.ShowRequest`、完了コールバック同一性で自分の入力だけを識別 | 他用途の名前入力への一律パッチ |
| `PresetUiController.Preview.cs` | 最高売上記録ページの `UICustomPartsListItem` を複製して表示。元Prefabを変更しない | 11枠固定の前提、外見の追従・非表示表示 |
| `AppearanceEditorPatches.cs` | 現在のUI状態に限定した入力・フッター処理 | 外見編集モード、全く同じショートカットの無条件横取り |
| `PresetStorage.cs` / `PresetModels.cs` | スロット番号を識別子にする、切り離した候補を保存、成功後だけメモリ更新、旧版・破損・未来版を区別 | CurrentAppearance、modelName、外見のMode |
| `Recovery.cs` | 復旧処理を独立して試行し、不完全な復旧を成功扱いにしない | 外見Rendererの復元処理 |

実装は独立したDLL・名前空間・設定・翻訳IDとする。Transmogの参照DLL、設定読込、相互呼出し、共有状態は不要。

## 3. 名前入力不具合への対応

0.1.0は `PanelTextInput.cs` の `GUI.Button` と `Event.current` による自作入力。
今回の `LogOutput.log` は起動成功と編集取消まで記録されているが、入力イベントの情報や例外はなく、入力不能の原因は確定できない。
以前の「貼り付けで入力できる」という案内は実機で裏付けられていなかった。

自作入力とOnGUIパネルを廃止し、Transmogで使われている次の方式へ移行する。

- `KeyboardManager.ShowRequest(KeyboardType.BuyPetAnimal, initialText, completeCallback, cancelCallback, false, true)` を入力UIの入口として使用する。ペット購入・命名データの更新処理は呼ばない。
- Successで名前を検証してMod専用プリセットを保存。Cancelは保存せず元のスロット一覧へ戻る。
- 入力コールバックのネイティブポインタが一致する間だけ、案内文・取消ボタンを調整する。
- デリゲートを存続させ、画面を閉じた後や別セッションの遅延コールバックを無視する。
- キーボードUIの終了を待って次のダイアログを開く。時間経過だけで終了扱いにしない。
- 日本語IME・英数字・ゲームパッド・取消を実機確認する。文字数上限は標準入力UIの実際の制限を調査し、保存形式の上限と区別する。

## 4. 操作と画面

通常の「オブジェの変更」画面から「配置プリセット」を開く。
入口は通常のオブジェ変更画面の＋操作とし、標準ダイアログを開く。確認用のF8操作は廃止。Transmogとの併用判定は任意依存の公開API v1を優先する。
Transmogと同じ `UIMenuManager.OnStart` の無条件フックは採用しない。
ゲームパッド用の入口は通常編集画面の既存アクションとフッターの空きを確認して割り当てる。名前入力・一覧内の操作は標準UIに任せる。
追加ガイドは自分の要素だけを付け外しし、フッター全体を置換しない。他のダイアログ表示中・通常配置の選択画面と確認できない状態では入口を無効にする。

| 操作 | 画面遷移と結果 |
|---|---|
| 保存 | 保存 → 6スロット一覧 → 使用済みなら上書き確認 → 標準名前入力 → 保存完了 |
| 読込 | 読込 → 6スロット一覧と内容プレビュー → 決定時に全件検証 → 編集配置へ反映 → 通常編集へ戻る |
| 削除 | スロット一覧の削除操作 → 確認 → 選択スロットだけ空にする |
| 取消 | 名前入力からは一覧、一覧からはメニュー、メニューからは通常編集へ戻る |
| 配置の確定 | 通常編集側の既存の確定・取消を使用する |

名前は表示ラベルなので同名を許可する。空スロットは「未登録」。空スロットの読込は何も変更しない。
プリセット保存・削除はその場で永続化し、通常の装飾編集取消では取り消さない。この点は画面の文言で区別する。
保存するのは選択済みの編集配置であり、カーソルを合わせただけの候補モデルではない。

読込前の右側プレビューには位置、アイコン、オブジェ名を表示。実店舗モデルは一覧カーソル移動で変更しない。
効果の要約はゲームの集計APIが副作用なく使用できることを確認して追加する。初期段階では通常編集に戻った後の標準効果表示を使う。
所持不足・枠不足は「小オブジェ：○○が1個不足」のように表示し、無言で部分適用しない。

## 5. 保存モデル

テント・棚・小／大オブジェを保存対象とし、特殊オブジェは通常UIでの合法な枠・削除規則を実機確認できた場合に対応する。
カテゴリと枠数は現在のゲームデータから取得し、Transmogの固定11枠をコピーしない。

```text
SchemaVersion: 2
Presets[]
  SlotId: 1..6             # 名前とは独立した識別子
  Name
  Slots[]
    Category
    Index
    ItemId                # 実配置のuint ID
```

バフ数値、modelName、GameObject、棚拡張回数、ゲームセーブ識別子は保存しない。
現在の配置の正本はゲームに置く。Mod側にCurrentLayoutを永続化して起動時に適用する仕組みは作らない。
プリセットは環境内で共有するが、別セーブへの読込でも必ずそのセーブで検証する。

保存先は既存の `BepInEx/config/com.icy.bazaardecorpresets.presets.json` を維持する。設定cfgとは分離。
一時ファイル書込・flush・原子的置換・前回正常版のバックアップを使う。
破損時は正常バックアップから読込可能にし、修復保存前に破損原本を保全する。未来版は破損扱いせず、自動復旧・上書きを停止する。
保存失敗時にはメモリ上のプリセットも更新しない。ログ出力失敗を保存失敗扱いにしない。

0.1.0データはコピーした候補から移行し、元ファイルを保全する。6件以下なら順番に割当て、7件以上なら無断切捨てせず取込対象を選べるまで旧データを読取専用で保持する。

## 6. 実配置適用の境界

0.1.0の「SetCustomPartsを順に呼び、失敗後に逆操作」は原子的ではない。逆操作が失敗しても通常確定へ進める構造は採用しない。
UIの `IsLock` と `Data.Stack` だけから装備済みを含む総所持数を推測する現方式も置き換える。

### 適用前

1. 通常編集の準備完了、対象ページの一致、別ダイアログ・ロード・終了処理がないことを確認する。
2. 現在の編集配置と確定済み配置を、ネイティブのリストを共有しない通常C#の値へ保存する。
3. ID存在、カテゴリ、所持／DLC利用可否、解放済み枠、空欄可否、棚の構成制約を検証する。
4. 所持数の正本と「配置中を含むか」を通常の1個選択・複数配置・入替えで検証する。`IsBaseParts`を無条件で無限所持とする推測も廃止する。
5. 完成後の構成全体で数量を検証する。現在配置と所持数を無条件に加算しない。配置済み個体を交換する中間状態も扱える適用順序を確認する。
6. 保存側にしか存在しない枠があれば全件拒否。現セーブで追加された枠は現状維持とし、その分も数量検証に含める。

### 適用中・適用後

- ゲームの正常な編集経路（`SetCustomParts`等）を実証して利用する。`FromSaveData`や確定済み配置の直接代入を代替手段にしない。
- 検証完了後にだけ編集へ渡し、適用中は対象編集画面の選択と確定を一時的に止める。名前入力など他UIの入力は止めない。
- 編集IDが期待値と一致し、確定済み配置・所持数・進行度が変わっていないことを確認する。
- モデル更新・標準効果表示の完了をゲームの実際の完了通知／状態で確認する。「2フレーム待つ」やsetterのreturnだけを成功としない。
- 成功後に通常編集へ戻す。ユーザーが通常操作で確定するまではゲームの確定済み配置を変更しない。
- ModのJSONへ保存できないことは、ゲーム側の既存配置や通常編集の動作に影響させない。

### 失敗時

変更前の拒否なら元の編集を継続する。適用途中の失敗ならそのセッションのプリセット機能を停止する。
編集スナップショットへの復帰を検証し、復帰できなければゲームの通常取消経路で編集全体を終了する。通常取消でそれ以前の手動編集も破棄される場合は通知する。
復帰・取消が確認できない状態で確定操作を解放しない。自分のUIと一時入力制御は個別に後片付けする。
取消経路と非同期ロード終了を実証できることを適用機能の有効化条件とする。
この経路が安全と確認できなければ、UI・保存・読取専用プレビューまでを先に提供する。

## 7. 構成と状態管理

| コンポーネント | 責務 |
|---|---|
| Plugin / Patches | 狭い条件のフック登録。登録途中失敗時に自分のフックのみ解除 |
| EditorSession | 編集開始／終了、世代ID、状態、スナップショット。別セーブ・別画面へ持ち越さない |
| NativePresetUi | メニュー・一覧・通知・フッター。所有するUIだけ閉じる |
| NativeNameInput | KeyboardManager要求、本人確認、結果・取消 |
| PresetPreview | 標準行の複製、位置・アイコン・名前。複製だけ破棄 |
| LayoutValidator | ゲームから読み取った事実に基づく、純粋な全件検証 |
| LayoutApplier | 適用・照合・復元・取消。通常セーブを呼ばない |
| PresetStore | スキーマ・移行・原子的保存・復旧。Unity非依存 |
| Localization | 独立した日英文言。既存ゲーム文字列を永続的に変更しない |

状態は `Closed → EditorReady → Menu → Slots → NameInput / Validating → Applying → EditorReady`。
書込失敗は保存前の状態へ、適用失敗は `Recovering → EditorReady / Closed` へ遷移する。
画面終了・ロード・失敗で世代を進め、古いコールバックを無効化する。デリゲートは要求単位で生成・保持し、前世代のものを再利用しない。
遅れて開いた自分のダイアログは所有確認後に閉じる。他の命名UIやバニラのセーブダイアログを閉じない。

## 8. 実装順と完了条件

1. **標準UI・名前入力**：保存／読込／削除、日英、取消復帰。実配置の読込はこの段階では無効。日本語IMEとゲームパッドの実機確認を先に行う。
2. **保存と内容表示**：6スロット、原子的保存、バックアップ復旧、旧版取込、標準行プレビュー。
3. **適用経路の実証**：通常操作のログで数量・更新順・取消を確認。1枠から始めて複数枠の交換へ進む。
4. **適用機能**：全件検証、正常終了・失敗復元の照合、通常確定・取消、マップ移動、ゲームセーブ再読込。
5. **撤去試験**：ゲーム終了後にDLLと専用データを外して同じセーブをバニラで開き、配置・所持品・通常編集が使えることを確認する。

自動テストは重複ID数量、交換、空欄、カテゴリ不一致、未解放枠、未知ID、スキーマ移行、保存拒否、未来版保護、遅延コールバック、適用の各段階の失敗と復旧を対象にする。
実機では標準入力・ダイアログ順序・モデル／効果・通常取消・Mod撤去後を確認する。純粋ロジックのテスト成功をゲーム内の安全性確認の代用にしない。

この設計で確定するのは「独立Mod」「標準UI」「6スロット」「通常編集への読込」「バニラ互換の保存境界」。
ゲームパッドの入口、特殊オブジェ、数量の正本、非同期完了・復旧の具体的な呼出し順は、実装前の実証事項として残す。
